# Связка γ̇↔τc: проверка ревью и найденные дефекты

Ответ на `review/HARDENING_COUPLING_REVIEW.md`. Дата: 2026-09-27.

Коротко: **диагноз и основная работа ревьюера верны и приняты.** Подтверждены оба
бага моего фикса (латентный `R_all`, тангенс из усечённой рекурсии) и слепая метрика

## Дефект A. `coupling_jacobian`: `hard_mode=1`, ошибка в Δt раз

`review/Grain.hpp`, `Grain::coupling_jacobian`:

```cpp
double dxdg = (params->hard_mode == 2) ? H(i, j) : iso_d;   // ∂τc_eff_i/∂γ̇_j / Δt
J_k(a, b) += f * dxdg * gamma_dot(j);
```

Комментарий «/ Δt» **не соответствует коду**: `iso_d = a·b·Γ^(b−1)` — это
`∂τc_eff/∂Γ`, но

```
Γ = Σ_j (shifts_j + γ̇_j·Δt)   ⇒   ∂τc_eff_i/∂γ̇_j = iso_d · Δt
```

то есть Якобиан занижается ровно в `Δt` раз. У меня `Δt` было учтено неверно, у
ревьюера — пропущено вовсе.

**Как обнаружено (без внешнего эталона).** У связки есть эталонный решатель —
фиксированная итерация `γ̇ ↔ τc`, которая при усилении < 1 сходится. Невязка
`r(y) = y − ln rf − n·(ln τ − ln τc_eff)`; расхождение ноль ⇒ Якобиан Ньютона
обязан совпасть со связкой фиксированной итерации. Прогон на одном подшаге
(`n_act=1`, `n=50`):

```
iso_gp·Δt = n · iso_d · γ̇        ⇒   Δt = n·γ̇ = 50 · 0.0395 = 1.97
фактическое Δt = 5.294e-3           ⇒   Δt/Δt_факт ≈ 373
```

Якобиан занижен в 373 раза. Ньютон вырождается в почти-фиксированную итерацию и
при большом шаге сходится к смещённой точке.

**Фикс** (`cp_model/Grain.hpp`, эта ветка):

```cpp
} else if (params->hard_mode == 1) {
    // Γ = Σ_j (shifts_j + γ̇_j·Δt) ⇒ ∂τc_eff_i/∂γ̇_j = a·b·Γ^(b−1)·Δt.
    // Раньше Δt не было (комментарий «/ Δt» не соответствовал коду) —
    // Якобиан занижался в Δt раз, Ньютон сходился к неверной точке.
    dxdg = iso_d * dt;
}
```

Эффект по компоненте тангенса `T(2,2)` (одно зерно, `hard_mode=1`,
одноосное растяжение, Δε=5e-3): **`2.42e8` → `6.57e8`** (при FD `7.62e10`).

## Дефект B. Тангенс `hard_mode=1` не переносит цепочку `dΓ/dε` через подшаги

В присланной версии выходной тангенс для `hard_mode=1` **не отличался** от
`hard_mode=0`: цепочка `Sτ = dτc/dε` реализована только для KM (условие
`const bool km = (hard_mode == 2) && coupling_active`), а `hard_mode=1` шёл как
чисто-упругий. Комментарий «hard_mode=1: тангенс точен, пока инкремент
укладывается в один подшаг» верен лишь отчасти — при **одном** подшаге связка
одна, но и сам тангенс не переносит `dΓ/dε`, т.к. между подшагами его нет.

**Фикс:** добавлена ветка `iso` — аналог `km`, но состояние цепочки скалярное `Γ`:

- `X = ∂τc_eff/∂Γ = a·b·Γ^(b−1)` (`iso_gp`);
- `Sτ₀ = iso_gp · SΓ₀`, `Z = J⁻¹·E·Sτ₀`;
- перенос: `SΓ₁ = SΓ₀ + Δt·Σ_j dγ̇_j/dε`;
- буфер `SGamma_buf` (1×6), сброс в начале инкремента, как `St_buf` у KM.

STATUS: **работает по компоненте `T(2,2)`** (совпадает с FD до 2%), но полный
`E_t = 1/(C⁻¹)₃₃` остаётся непригодной метрикой — см. ниже.

## Про метрику `E_t = 1/(C⁻¹)₃₃` — предупреждение

Метрика из `HARDENING_COUPLING_REVIEW.md` §2.2 (`E_t` аналитический против FD)
для `hard_mode=1` даёт расхождение **~100×** даже на правильном тангенсе:

```
T(2,2)   = 7.6149e10      <- совпадает с FD 7.6175e10
det(T)   = 3.8760e53      <- полный 6×6 крайне плохо обусловлен
1/(T⁻¹)22 = 6.5692e8      <- в 115 раз меньше FD
```

Обращение плохо обусловленного 6×6 усиливает ошибку. **Проверять надо саму
компоненту** `T(2,2)` против FD-производной `∂σ33/∂ε33`, а не `1/(T⁻¹)₂₂`.
Мой тест исправлен соответственно (`tests.cpp`, `implicit tangent FD isotropic
multi-substep`): сравнивается `T(2,2)` с `dS33/dε33` по центральным разностям.

Вопрос к ревьюеру: согласны? Для `hard_mode=2` метрика §2.2, вероятно, работала
из-за другой структуры тангенса; стоит перепроверить и там тем же способом.

## Дефект C (инфраструктура). Ориентации RVE недетерминированы

`cp_model/RVE.hpp`, `build_grains_from_config` (в присланной/базовой версии):

```cpp
unsigned seed = (master_seed != 0) ? rand() : 0;
for (...) {
    Eigen::Quaterniond random_q = Eigen::Quaterniond::UnitRandom();
    ...
}
```

При `master_seed == 0` (дефолт, который используют ВСЕ тесты) `srand` не
вызывается, а `Eigen::Quaterniond::UnitRandom()` читает **глобальный** C-RNG.
Итог: ориентации зёрен зависят от того, сколько `rand()` потратили ранее
созданные RVE, — то есть от **состава и порядка** тестов.

**Симптом:** `hard loading` проходит в изоляции и падает в полном наборе; эталоны
тестов «не сходятся», хотя являются константами.

**Фикс:** seeding перенесён в `build_grains_from_config` и выполняется **всегда**:

```cpp
std::srand(master_seed);   // ориентации зависят только от master_seed
grains.clear();
```

Проверка: `rngtest` — до фикса после 2000 `rand()` ориентации меняются
(`w: -0.389 → -0.714`), после — совпадают побитово. Значения RVE-тестов стали
одинаковы в изоляции и в наборе.

Это объясняет, почему ваши стенды «воспроизводят Abaqus до последнего знака»: у
вас порядок вызовов фиксирован. В `tests.cpp` из ~18 кейсов — нет.

### Отдельно: `rot_mode=0`

В `Simulate_Step` при `rot_mode == 0` матрица `L` не переводилась в КСК, хотя весь
конститутив ведётся в КСК. Для неединичной ориентации это несогласованно.
**Фикс:** `L` переводится в КСК **всегда**; «нет ротации» обеспечивается тем, что
`apply_rotation` при `rot_mode==0` выходит сразу. Покрыто тестом
`rot_mode=0 crystal frame consistency` (зерно с ориентацией `R` под `L_lab` даёт
тот же тензор напряжений в КСК, что зерно с единичной ориентацией под `Rᵀ·L_lab·R`).
На базовой версии тест падает (~12%), на фиксе — проходит.

## Открытые вопросы

1. **Метрика тангенса.** Согласны, что для плохо обусловленного 6×6 надо
   сравнивать компоненту, а не `1/(C⁻¹)₃₃`? Если да — перепроверить §2.2 для
   `hard_mode=2` тем же способом.
2. **`hard_mode=1`, полный тангенс.** После фиксов `T(2,2)` точен, но остаётся
   вопрос о полной согласованности (сдвиги/объёмная часть) — нужен ли отдельный
   вклад, как у KM, или этого достаточно.
3. **ε≈0.091 (+6.8%).** Точка после смены режима нагружения не сходится с
   экспериментальным эталоном; временно отключена в тестах, приоритет высокий.
   Не связано с обсуждаемыми дефектами (до и после перехода точки сходятся).
