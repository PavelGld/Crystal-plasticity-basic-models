# CP-UMAT: NLGEOM=YES — как правильно и почему вариант с DFGRD не работал

Дата: 2026-09-07.

## 1. Суть в одном абзаце

При `NLGEOM=YES` Abaqus/Standard **сам ведёт коротационный базис** для UMAT: `DSTRAN` приходит как
приращение логарифмической деформации, уже повёрнутое за жёсткое вращение инкремента; входной
`STRESS` уже повёрнут на `DROT`; сама `DROT` передаётся, чтобы UMAT мог так же повернуть свои
тензорные state variables. Наша модель — гипоупругая, σ̇ = P:(D − Dᵖ) в системе решётки — это ровно
формулировка «малые деформации в коротационном базисе». Поэтому для больших деформаций нужно
изменить **одну вещь**: применить `DROT` к ориентации решётки. `DFGRD0/DFGRD1`, полярное
разложение, матричный логарифм — не нужны (они для гиперупругих / тотально-лагранжевых моделей).

## 2. Что изменено

### `cp_umat.cpp` (`umat_()`, после установления состояния, перед `step`)
```cpp
if (DROT) {
    Eigen::Matrix3d dR;   // Fortran column-major: DROT(I,J) = DROT[i + j*3]
    for (i,j) dR(i,j) = DROT[i + j*3];
    if ((dR - I).norm() > 1e-15) g->rotate_lattice(dR);
}
CPUMAT::step(g, DSTRAN, *DTIME, STRESS, DDSDDE, PNEWDT);   // как раньше
```
Логика: наше состояние хранится в кристальной системе, а `σ_lab = R_lat σ_cr R_latᵀ`. Abaqus повернул
свой базис на `DROT`, значит `σ'_lab = DROT σ_lab DROTᵀ = (DROT·R_lat) σ_cr (DROT·R_lat)ᵀ`, т.е.
`R_lat ← DROT·R_lat`. Побочный (и правильный) эффект: спин решётки становится полным тейлоровским
Ω = W − Wᵖ — W приходит через `DROT`, Wᵖ вычитается в `Simulate_Step` как прежде. При `NLGEOM=NO`
`DROT = I`, код универсален.

Полярное разложение, `matrix_log`, флаг `nlgeom` и изменённая сигнатура `Simulate_Step` — удалены;
`step()` вернулся к версии до NLGEOM-правок.

### `Grain.hpp` (+8 строк)
```cpp
void rotate_lattice(const Eigen::Matrix3d& dR);   // orient_q = q(dR)*orient_q; R_buf, T_voigt_valid
```
Базируется на версии из `cp_perf` (предиктор + O(n) KM + `DS_CRITICAL_IMPL=2.5e-4`).

## 3. Доказательство — `tests/test_nlgeom.cpp`

Простой сдвиг γ̇ = 0.1 с⁻¹ до γ = 0.3 (спин максимален, решётка поворачивается на 8.5°).
Эталон — standalone `Grain::Simulate_Step` с полным L = D + W. Проверяемое — путь UMAT, куда
подаются Abaqus-стиль величины: `dF = exp(L·dt) = dV·dR`, `DSTRAN = log(dV)` (инженерные сдвиги,
порядок Abaqus), `DROT = dR`.

| | |σ_ref − σ_umat|/|σ_ref| | |q_ref − q_umat| |
|---|---|---|
| n=20, 300 инкрементов | 1.2e-4 | 2.6e-5 |
| n=20, 1200 инкрементов | 6.4e-5 | 1.9e-5 |
| n=50, 600 инкрементов | 1.4e-4 | 2.3e-5 |
| **DROT проигнорирован** (прежнее поведение) | **2.8e-1** | **8.6e-2** (≈5°) |

Расхождение убывает с dt (порядок применения поворотов внутри инкремента, O(dt)). Без `DROT` —
28% по напряжению: именно так «малые деформации» врали при вращении.

## 4. Почему падал вариант агента

- `Eigen::EigenSolver` для **несимметричного** `dF` даёт комплексные собственные значения;
  `.real()` от них — мусор, `log` от отрицательных/нулевых — NaN → первый же инкремент.
- `L = logm(dF)/dt` уже содержит вращение, и сверху ещё применялся `R_rot` — двойной поворот.
- `F0 = F1 = I` в дампе — не ошибка: Abaqus передаёт нулевые приращения на старте шага
  (документация UMAT: «passes zero strain increments … to start the first increment»).
- Гипотеза про «spatial tangent со stress stiffening» — неверна: геометрическую жёсткость Abaqus
  собирает на уровне элемента сам. От UMAT нужен только материальный якобиан; наш коротационный
  тангенс — стандартное приближение, поправка ~σ/C ≈ 1e-3 (см. §6).

## 5. Что проверить в Abaqus

1. `tension_343el_nlgeom.inp` как есть (`*STEP, NLGEOM=YES`, `DROT` теперь используется).
   Замечание: в нём `U3 = 1.0` на единичном кубе — 100% номинальной деформации с одним зерном на
   элемент; для первого прогона имеет смысл 0.2–0.3, а до 1.0 идти после проверки, что сетка не
   вырождается.
2. Сверка с `NLGEOM=NO` на малой деформации (до ε = 0.02): S33 должно совпасть в пределах ~1e-3.
3. Полюсные фигуры из SDV7–10 (кватернион) при ε ≥ 0.5 — сравнить с вашей standalone-валидацией
   (`<111>||ND` для FCC tension). Это главная физическая проверка больших деформаций.
4. Если сходимость заметно хуже, чем при `NLGEOM=NO`, — см. §6 (поправка тангенса).

## 6. Известные приближения (не блокируют)

- **Тангенс.** Abaqus при NLGEOM=YES ожидает якобиан относительно яумановской скорости напряжений
  Кирхгофа: `C_abq = C_mat + σ⊗I` (в компонентах `C_ijkl += σ_ij δ_kl`, в Фойгте — прибавить
  `σ_v(I)` к столбцам J = 0..2). Наш C — коротационный материальный; разница ~σ/C ≈ 1e-3 влияет
  только на скорость сходимости. Добавить одной строкой в `step()`, если понадобится.
- **Cauchy vs Kirchhoff.** Гипоупругая интеграция даёт σ с точностью до множителя J = det F ≈ 1 +
  tr(εᵉ) ~ 1e-3 для металлов. Игнорируется.
- **`F`, `strain_gl` в Grain** по-прежнему не сериализуются в STATEV — на напряжения и ориентацию
  не влияют (кинематика теперь целиком от Abaqus), но выводить деформацию из UMAT нельзя.
- Порядок «сначала DROT на весь инкремент, затем Wᵖ по подшагам» — ошибка O(dt·|Ω|²), см. таблицу.
