# Проблема: упрочнение зависит от скорости деформации

Дата: 2026-09-20. Контекст: CPFEM UMAT, неявная схема (`integ_mode=1`),
Kocks-Mecking (`hard_mode=2`).

---

## 0. TL;DR

**Симптом.** При **одинаковом накопленном сдвиге** упрочнение `tc` и напряжение
сильно зависят от скорости деформации. Для n=50 (почти rate-independent) этого
быть не должно.

**Причина.** В `Grain::evaluate_Dp` связка `γ̇ ↔ τc_eff` решается наивной
фиксированной итерацией с **фиксированным числом sweep'ов (=3)**. У этой
итерации усиление `≈ n·H·Δγ/τc`; при большом `dt` оно > 1, итерация
**расходится** (колеблется), а код берёт произвольный 3-й sweep → упрочнение
почти случайно.

**Предложенный фикс** (уже в `cp_model/Grain.hpp`): демпфированная в
лог-пространстве итерация с контролем сходимости и адаптивным включением
демпфирования. Проверено: fast/slow дают одинаковое упрочнение и одинаковое
напряжение (±0.2%).

**Открытый вопрос:** фикс добавляет итераций → расчёт замедлился (нужно
замерить/оптимизировать, см. §6).

---

## 1. Как воспроизвести

Один элемент (`examples/01_single_element/tension.inp`), одинаковый материал,
одинаковая конечная деформация 10%, но разная **скорость**:

- **fast**: `*STATIC 0.005, 1.0, ...`  → деформация 0.1 за время 1.0  (rate 0.1)
- **slow**: `*STATIC 5.0, 100.0, ...`  → та же деформация за время 100  (rate 0.001)

Геометрия, материал, ГУ, число точек — идентичны. Разница только в длительности шага.

---

## 2. Наблюдение (до фикса)

Кривые напряжения (S33, МПа):

| ε | fast (rate 0.1) | slow (rate 0.001) |
|---|---|---|
| 0.01 | 16.31 | 14.59 |
| 0.02 | 18.69 | 14.67 |
| 0.05 | 28.75 | 14.92 |
| 0.08 | 38.90 | 15.20 |
| 0.10 | **43.98** | **15.41** |

Разница **в 2.9 раза**. И главное — в конце:

| | fast | slow |
|---|---|---|
| накопленный сдвиг `Σ|γ|` | 0.243 | 0.244 |
| `tc` в конце | **18.2 / 19.0** | **6.37 / 6.40** (почти `tc0=6`) |

**Одинаковый сдвиг → разное `tc` в 3 раза.** Это и есть баг: в модели
Kocks-Mecking упрочнение должно быть функцией накопленного сдвига, а не скорости.

---

## 3. Локализация

Проблема в связке **γ̇ ↔ τc_eff внутри одного инкремента**.

`τc_eff` (критическое напряжение на конце шага) зависит от `γ̇`:
```
τc_eff(i) = tc(i) + Σ_j H(i,j)·γ̇_j·dt
```
А `γ̇` зависит от `τc_eff` (степенной закон):
```
γ̇(i) = rate_factor · (τ(i)/τc_eff(i))^n
```

Это неявная связка, решается итерацией. Чувствительность:
```
∂ln γ̇ / ∂tc_eff = −n / tc_eff
```
При `n=50`, `tc≈6.4` это `−7.8`: **изменение `tc_eff` на 0.55 МПа меняет `γ̇` в
`e^4.3 ≈ 74` раза.**

---

## 4. Доказательство: итерация расходится

Дамп последовательных sweep'ов в `evaluate_Dp` (slow, `dt=1.667`):

```
sweep=0: sum_gdot=0.00236   Δtc=0
sweep=1: sum_gdot=3.03e-05  Δtc=0.547     ← γ̇ упал в 78 раз
sweep=2: sum_gdot=0.00222   Δtc=0.007     ← вернулся
```

Итерация колеблется: `γ̇` прыгает на порядки, `Δtc` прыгает между 0.55 и 0.007.
Код фиксирует **3-й** sweep — фактически произвольную точку цикла.

Для сравнения, тот же дамп при малом `dt` (fast, `dt=0.005`) **сходится**:
```
sweep=0: γ̇=0.00236
sweep=1: γ̇=0.00222  (≈ то же)
sweep=2: γ̇=0.00222  (сошлось)
```

**Условие расходимости:** усиление `n·H·Δγ/τc > 1`. При малом `dt`
(малый `Δγ`) — выполняется; при большом — нет.

---

## 5. Почему это выглядело как «зависимость от скорости»

`Δtc = H·γ̇·dt`. В slow-прогоне `dt` в 1000 раз больше, поэтому `Δtc` за подшаг
(≈0.55 МПа) намного больше, чем в fast (≈0.0001 МПа «на глаз», но при 200 шагах
суммарно то же). Сильное `Δtc` → сильное усиление → расходимость итерации.
Поскольку она берёт произвольный sweep, итоговое упрочнение оказалось
**в 3 раза меньше** — что внешне выглядит как «медленная деформация → слабое
упрочнение».

## 6. Предложенный фикс и что проверить

**Фикс** (`cp_model/Grain.hpp`, `evaluate_Dp`): вместо 3 фиксированных sweep'ов —
итерация с **контролем сходимости** и **демпфированием в лог-пространстве**,
причём демпфирование включается **адаптивно** (старт без него; включается,
только если поправка перестала убывать):

```cpp
double relax = 1.0;                 // старт без демпфирования
for (int s = 0; s < max_sweeps; s++) {
    // tc_eff из γ̇; γ̇_new из τc_eff (log-пространство, демпфирование relax)
    ...
    if (max_chg < conv_tol) break;
    if (max_chg >= prev_chg) relax *= 0.5;   // поправка не убывает → демпфируем
}
```

**Результат (тот же тест fast/slow):**

| | fast | slow |
|---|---|---|
| S33 при ε=0.1 | **49.81 МПа** | **49.71 МПа** |
| разница | | **−0.2%** (было −65%) |
| `tc` в конце | 20.57 | 20.45 |

Модель стала rate-independent (правильно для n=50). **Все 16 автотестов
проходят** (включая `implicit tangent FD`, `big step x10/x50`, медленные
`* equivalence`, 364 с и 1031 с).

### Что нужно от ревьюера

1. **Корректен ли предложенный способ решения связки** `γ̇ ↔ τc_eff`?
   - Достаточно ли адаптивного демпфирования, или нужен честный итерационный
     решатель (Ньютон по `tc_eff` / по `γ̇`)?
   - Обоснован ли пересчёт `G` (консистентного тангенса) при новом числе sweep'ов —
     в коде `G` собирается отдельным фиксированным циклом (`g_sweeps = min(sweeps,4)`).
2. **Критерий сходимости** `max|Δln γ̇| < 1e-7` — достаточно? Не влияет ли на
   тангенс (FD-тест)?
3. **Производительность.** Первая версия (жёсткое демпфирование 0.25) замедлила
   Neper-пример в 6 раз (8 → 51 мин). Адаптивный вариант — замер в процессе.
   Если всё ещё медленно: альтернатива — ограничивать **подшаг по усилению**
   `n·H·Δγ/τc < ~0.5` (тогда 3 sweep'ов хватает), либо отдельный критерий в
   `DS_CRITICAL_IMPL`.
4. **Изменение результатов.** Фикс меняет напряжения (single element: 44 → 49.8
   МПа) — ожидаемо, т.к. старые значения были получены с расходящейся итерацией.
   Нужно перепроверить ранее «прогнанные» валидации (343-el, Neper-текстуры):
   текстуры устойчивы, но абсолютные уровни сдвинутся.
