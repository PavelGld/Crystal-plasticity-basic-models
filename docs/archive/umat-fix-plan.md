## Реализованные исправления (все верифицированы)

### Баг #1 (ПЕРВОПРИЧИНА): Eigen aliasing в CPUMAT::step

```cpp
// БЫЛО:
sv.noalias() = V_to_A() * sv;
// СТАЛО:
sv = (V_to_A() * sv).eval();
```

`noalias()` при самоприсваивании заставляет Eigen писать результат прямо в `sv` во время умножения — строка 5 матрицы `V_to_A` (Abaqus-компонента σ₂₃) читает `sv(3)`, который уже перезаписан строкой 3. Каждый вызов UMAT возвращал `STRESS[σ₂₃] = σ₁₂/2`, а истинное σ₂₃ терялось.

Почему не видно раньше:
- Баг живёт только в UMAT-обёртке (standalone Grain/RVE его не видят)
- При identity-растяжении σ₁₂ = σ₂₃ = 0 — все identity-кейсы проходили
- DDSDDE считался через те же матрицы правильно → Abaqus получал верный тангенс + неверное напряжение

### Баг #2: P_v(3,3) = c44 → 2·c44

В doubled-shear Voigt конвенции корректный кубический закон требует `P_v(3,3..5,5) = 2·c44`.

### Баг #3: load_state не восстанавливает H (Kocks-Mecking)

Добавлен вызов `update_H_KM_if_needed()` после `set_tc_all()` в load_state.

### Баг #4: Протухший тангенс при провале Ньютона

Добавлен флаг `step_failed`, при срабатывании которого `PNEWDT = 0.25` (Abaqus режет шаг).

### Баг #5: Chain tangent через подшаги

`tangent_buf` накапливается по цепочке: `C ← J⁻¹(C_prev + w·P_eff)` где w = dt_sub/dt_inc.

## Multi-element convergence — RESOLVED

**Root cause:** Eigen aliasing bug in `CPUMAT::step()`:
```cpp
sv.noalias() = V_to_A() * sv;  // BUG: noalias with self-assignment corrupts data
```
Row 5 of `V_to_A` reads `sv(3)` which was already overwritten by row 3. Every UMAT call returned `STRESS[σ₂₃] = σ₁₂/2`, true σ₂₃ lost.

**Fix:** `sv = (V_to_A() * sv).eval()` — forces temporary.

**Verification:**
- 8 elements random: ✅ converges, S33 scatter 12-15 MPa
- 343 elements random (7×7×7): ✅ **3 часа CPU, 0 errors**, S33 per element 27-74 MPa (102.5% variation — texture effect)

## Диагноз ревьюера (проверен численно на numpy)

Симптоматика «identity работает в любом количестве; один повёрнутый элемент еле сходится; восемь повёрнутых умирают» **почти однозначно указывает на тангенс при R ≠ I**. Причина — не кэш `T_voigt`, а сама матрица `computeVoigtRotationInPlace` и способ её применения.

## Баг №1 (ПЕРВОПРИЧИНА): `T_voigt` неверна для нашей конвенции Фойгта, и `T·C·Tᵀ` — неверная конгруэнция

Наша конвенция: `tensorToVoigtInPlace` даёт **удвоенные сдвиги И для напряжений, И для деформаций** (`v(3) = σ23+σ32 = 2σ23`). Такой вектор преобразуется при повороте как *инженерная деформация*, а не как классический стресс-Фойгт.

Правильные коэффициенты в текущей структуре цикла (где каждая сдвиговая пара посещается дважды):

| Переход | Сейчас (код) | Должно быть |
|---------|--------------|-------------|
| норм→норм | `+v` | `+v` ✅ |
| сдвиг→сдвиг | `+v` (в 2 раза больше) | `+0.5·v` |
| норм→сдвиг | `+0.5·v` (в 2 раза меньше) | `+1.0·v` |
| сдвиг→норм | `+2.0·v` (в 4 раза больше) | `+0.5·v` |

Численная проверка ревьюера: `|T_current·v − t2v(RSRᵀ)| ≈ 17.8` (‖v‖~O(1)), исправленная — `≈ 2e-15`.

**Вторая половина бага:** даже с правильной `T` формула `T·C·Tᵀ` неверна, потому что в этой конвенции `T⁻¹ ≠ Tᵀ`. Правильно:

```
C_lab = T(R) · C_cr · T(Rᵀ)
```

(обратное преобразование строится тем же кодом от `R_buf.transpose()`, а не транспонированием). Проверка: `T(R)·P·T(R)ᵀ` даёт ошибку ~1e5 МПа, `T(R)·P·T(Rᵀ)` — 1e-10.

**Почему объясняет симптомы:** `get_stress_lab()` поворачивает напряжение напрямую как тензор (правильно), а `DDSDDE` идёт через сломанную `T_voigt`. При identity `T = I` — всё маскируется. При одном повёрнутом элементе Abaqus получает неправильный, но не безумный тангенс → глобальный Ньютон деградирует, режет шаг (наблюдение «200 инкрементов не хватает, останавливается на 0.75»). При 8 ориентациях — 8 по-разному неправильных жёсткостей → Ньютон не сходится вовсе.

### Реализовано ✅

```cpp
inline void Grain::computeVoigtRotationInPlace(Matrix6d& T, const Eigen::Matrix3d& R) const {
    T.setZero();
    for (int p = 0; p < 3; ++p)
        for (int q = 0; q < 3; ++q) {
            int P = tensorToVoigtIndex(p, q);
            bool P_shear = (p != q);
            for (int i = 0; i < 3; ++i)
                for (int j = 0; j < 3; ++j) {
                    int I = tensorToVoigtIndex(i, j);
                    bool I_shear = (i != j);
                    double v = R(i, p) * R(j, q);
                    if (!P_shear && !I_shear)       T(I, P) += v;          // norm->norm
                    else if (P_shear && I_shear)    T(I, P) += v * 0.5;    // shear->shear
                    else if (!P_shear && I_shear)   T(I, P) += v;          // norm->shear
                    else                            T(I, P) += v * 0.5;    // shear->norm
                }
        }
}

inline void Grain::get_tangent_lab_into(Matrix6d& result) const
{
    if (!tangent_valid) { get_elasticity_lab_into(result); return; } // UMAT fallback
    if (!T_voigt_valid) {
        computeVoigtRotationInPlace(T_voigt_buf, R_buf);
        computeVoigtRotationInPlace(T_voigt_inv_buf, R_buf.transpose());  // новый буфер
        T_voigt_valid = true;
    }
    Buf_P.noalias() = T_voigt_buf * tangent_buf;
    result.noalias() = Buf_P * T_voigt_inv_buf;
}
```

То же самое в `get_elasticity_lab_into`. `T(R)·T(Rᵀ) = I` выполняется точно (~5e-16), кэшировать обе матрицы можно под тем же `T_voigt_valid`.

### Результат

## Баг №2: `P_v(3,3) = c44` неверно и в кристальном фрейме

В нашей конвенции (удвоенные сдвиги у σ_v, инженерные у D_v) корректный кубический закон требует `P_v(3,3..5,5) = 2·c44` (ошибка ~8.6e4 МПа при c44).

Сейчас компенсируется лишней ×2 в `A_to_V` — но **только пока R = I**. При повёрнутом зерне удвоенные лабораторные сдвиги D перемешиваются с нормальными компонентами при переходе в КСК — компенсация разваливается:
- у повёрнутых элементов даже *упругий* отклик неверен
- `computeDeviatoricDu` завышен → неправильный `rate_factor_impl` → неправильная пластическая кинетика

Исправлять **парой**:
1. `A_to_V` → чистая перестановка (3↔5, без ×2)
2. `P_v(3,3) = 2*c44` — и в UMAT, и в standalone (иначе разъедутся)

После этого `DDSDDE = V_to_A · T_lab · A_to_V` автоматически попадёт в конвенцию Abaqus.

### Реализовано ✅

- `cp_model/MaterialParams.hpp`: `P_v(3,3) = P_v(4,4) = P_v(5,5) = 2.0 * c3;`
- `cp_umat/cp_umat_types.hpp`: `A_to_V` — чистая перестановка (без ×2)
- `cp_umat/cp_umat.cpp`: `init_params` `P_v(3,3)=2.0*c44;`

## Баг №3: `load_state` не восстанавливает матрицу `H` (Kocks-Mecking)

`H` — член `Grain`, эволюционирует через `update_H_KM()` от текущих `tc`. При переиспользуемом singleton на точку B приходит `H`, посчитанная от `tc` точки A. `evaluate_Dp` и `G_buf` (→ тангенс) используют чужую `H`.

При identity все точки идентичны — невидимо. При случайных ориентациях `tc` у точек расходятся с первого пластического инкремента — все IP взаимно заражают упрочнение.

**Фикс:** `H` — детерминированная функция `tc`:
- сделать `update_H_KM` публичным (или пересчитывать внутри `set_tc_all` при `hard_mode==2`)
- в `load_state` после `set_tc_all` вызвать пересчёт `H`

Также: на второй итерации равновесия в одном инкременте `load_state` возвращает `tc` на начало инкремента, а `H` остаётся от конца предыдущей итерации — пересчёт H решает и это.

### Реализовано ✅

```cpp
void CPUMAT::load_state(Grain* g, const double* STATEV) {
    ...
    g->set_tc_all(tc); g->set_shifts_all(shifts);
    if (g->get_H().rows() > 0) g->update_H_KM();  // recompute H from restored tc
    g->set_sim_time(STATEV[67]); g->set_acc_def(STATEV[68]);
}
```

## Баг №4: при провале `solve_implicit` наружу уходит чужой/протухший тангенс без сигнала

При `MAX_FALLBACK_DEPTH` под `ABAQUS_UMAT` — молчаливый `return`. Дальше `step()` отдаёт:
- `STRESS` (частично обновлённый)
- `DDSDDE` из `tangent_buf`, где может лежать тангенс **другой точки** от предыдущего вызова
- `PNEWDT = 1.0` — Abaqus не знает о провале, жжёт попытки

**Фикс:**
1. прокинуть флаг неудачи (например, `tangent_valid = false` при провале) + проверка в `step()`
2. при провале `PNEWDT = 0.25` и возврат упругой матрицы
3. `reset_state()` должен сбрасывать `tangent_valid` — сейчас не сбрасывает

**Дополнительно:** проверить, что в `Grain.hpp` `get_tangent_lab_into` не содержит безусловный `throw` (с `/EHsc-` это abort всего анализа). В REVIEW_REQUEST описана версия с упругим фолбэком — убедиться, что в .obj попадает именно она.

### Реализовано ✅

```cpp
// solve_implicit fallback:
if (depth >= MAX_FALLBACK_DEPTH) {
    tangent_valid = false;  // signal: return elastic matrix, stale tangent discarded
    return;
}

// get_tangent_lab_into UMAT fallback:
if (!tangent_valid) {
    get_elasticity_lab_into(result);
    return;
}

// reset_state:
tangent_valid = false;
```

// v' = T(R)·v для векторов Фойгта с удвоенными сдвигами (наша конвенция σ и D)
inline void Grain::computeVoigtRotationInPlace(Matrix6d& T, const Eigen::Matrix3d& R) const {
    T.setZero();
    for (int p = 0; p < 3; ++p)
        for (int q = 0; q < 3; ++q) {
            int P = tensorToVoigtIndex(p, q);
            bool Ps = (p != q);
            for (int i = 0; i < 3; ++i)
                for (int j = 0; j < 3; ++j) {
                    int I = tensorToVoigtIndex(i, j);
                    bool Is = (i != j);
                    double v = R(i, p) * R(j, q);
                    if (!Ps && !Is)      T(I, P) += v;
                    else if (Ps && Is)   T(I, P) += 0.5 * v;
                    else if (!Ps && Is)  T(I, P) += v;        // норм→сдвиг: 1.0
                    else                 T(I, P) += 0.5 * v;  // сдвиг→норм: 0.5
                }
        }
}

inline void Grain::get_tangent_lab_into(Matrix6d& result) const

        T_voigt_valid = true;

    Buf_P.noalias() = T_voigt_buf * tangent_buf;
    result.noalias() = Buf_P * T_voigt_inv_buf;
}

В нашей конвенции (удвоенные сдвиги у σ_v, инженерные у D_v) корректный кубический закон требует `P_v(3,3..5,5) = 2·c44` (ошибка ~8.6e4 МПа при c44).

- у повёрнутых элементов даже *упругий* отклик неверен
- `computeDeviatoricDu` завышен → неправильный `rate_factor_impl` → неправильная пластическая кинетика

Исправлять **парой**:
1. `A_to_V` → чистая перестановка (3↔5, без ×2)
2. `P_v(3,3) = 2*c44` — и в UMAT, и в standalone (иначе разъедутся)

После этого `DDSDDE = V_to_A · T_lab · A_to_V` автоматически попадёт в конвенцию Abaqus.

Файлы: `cp_umat/cp_umat_types.hpp`, `cp_umat/cp_umat.cpp` (init_params), `cp_model/MaterialParams.hpp` (файловый парсер).

## Баг №3: `load_state` не восстанавливает матрицу `H` (Kocks-Mecking)

`H` — член `Grain`, эволюционирует через `update_H_KM()` от текущих `tc`. При переиспользуемом singleton на точку B приходит `H`, посчитанная от `tc` точки A. `evaluate_Dp` и `G_buf` (→ тангенс) используют чужую `H`.

При identity все точки идентичны — невидимо. При случайных ориентациях `tc` у точек расходятся с первого пластического инкремента — все IP взаимно заражают упрочнение.

**Фикс:** `H` — детерминированная функция `tc`:
- сделать `update_H_KM` публичным (или пересчитывать внутри `set_tc_all` при `hard_mode==2`)
- в `load_state` после `set_tc_all` вызвать пересчёт `H`

Также: на второй итерации равновесия в одном инкременте `load_state` возвращает `tc` на начало инкремента, а `H` остаётся от конца предыдущей итерации — пересчёт H решает и это.

## Баг №4: при провале `solve_implicit` наружу уходит чужой/протухший тангенс без сигнала

При `MAX_FALLBACK_DEPTH` под `ABAQUS_UMAT` — молчаливый `return`. Дальше `step()` отдаёт:
- `STRESS` (частично обновлённый)
- `DDSDDE` из `tangent_buf`, где может лежать тангенс **другой точки** от предыдущего вызова
- `PNEWDT = 1.0` — Abaqus не знает о провале, жжёт попытки

**Фикс:**
1. прокинуть флаг неудачи (например, `tangent_valid = false` при провале) + проверка в `step()`
2. при провале `PNEWDT = 0.25` и возврат упругой матрицы
3. `reset_state()` должен сбрасывать `tangent_valid` — сейчас не сбрасывает

**Дополнительно:** проверить, что в `Grain.hpp` `get_tangent_lab_into` не содержит безусловный `throw` (с `/EHsc-` это abort всего анализа). В REVIEW_REQUEST описана версия с упругим фолбэком — убедиться, что в .obj попадает именно она.
